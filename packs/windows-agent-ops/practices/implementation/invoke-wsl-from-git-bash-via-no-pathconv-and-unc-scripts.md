## When to apply

Apply when a Git Bash session - or an agent driving one - calls `wsl.exe` with a POSIX path argument or
with an inline multi-line shell command, and the result is a missing file, a corrupted argument, or
silently dropped `$VAR` / `$(...)` expressions.

## Guidance

Prefix the invocation with `MSYS_NO_PATHCONV=1` so `/`-prefixed arguments survive the MSYS layer:

```bash
MSYS_NO_PATHCONV=1 wsl.exe -d <distro> -- sh /tmp/diag.sh
```

Do not inline a non-trivial script in the command string. It passes through three interpreters - bash
quoting, MSYS argument conversion, and WSL's own shell - and `$` tokens are consumed long before the
script runs. Instead write the script to the distribution's filesystem through its UNC path and execute
the file:

```text
\\wsl.localhost\<distro>\tmp\diag.sh
```

Writing through the UNC share is a single file write from the Windows side, so `$`, quotes, and command
substitution can be used verbatim with no escaping. Keep the script LF-only and invoke it as
`sh /tmp/diag.sh` rather than depending on an execute bit.

## Why

Each layer of the call can rewrite characters: bash expands before anything else sees the argument,
MSYS converts path-shaped tokens, and the remote shell re-parses what remains. Debugging a mangled
one-liner means auditing all three, while a file written through the UNC path has only the file-write
layer to blame - and the conversion switch removes the path rewrite entirely.

## Exceptions and boundaries

A trivial invocation with no `$`, no quotes, and no leading-slash path needs neither guard. Keep both
habits anyway when the command is generated by a script or an agent, because such commands tend to grow
one of those elements later. The UNC path requires the distribution to be running; start it with a
no-op `wsl.exe` call first if the write fails, and do not assume `\\wsl.localhost` is available on
older Windows builds - fall back to a command string with both guards applied.

## Example

`wsl.exe -d Ubuntu sh /tmp/diag.sh` fails inside WSL with "cannot open" because the argument became a
Windows temp path. Writing the script over `\\wsl.localhost\Ubuntu\tmp\diag.sh`, then running
`MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -- sh /tmp/diag.sh`, executes it with the intended contents and
no escaping artifacts.
